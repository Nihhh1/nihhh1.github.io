# 加密文章使用说明

采用本地加密、浏览器解密：PBKDF2-SHA-256（600,000 次）派生密钥，AES-256-GCM 加密正文，每次生成随机盐和 IV。公开仓库不保存密码、密钥或正文原文。无需 GitHub Pages 自定义插件或后端。

## 首次准备

安装 Node.js 22 或更高版本，在项目根目录执行：

```sh
npm ci --prefix scripts
mkdir -p _private
```

`_private/` 已加入 `.gitignore` 和 Jekyll 排除列表。这个目录只在本地保存，请自行备份到私有位置；不要强制提交。加密脚本和依赖也不会发布到网站。

## 新文章

新建 `_private/2026-09-24-私密笔记.md`：

```markdown
---
title: 私密笔记
date: 2026-09-24
author: Ni
tags:
  - 随笔
---

## 正文

这里的内容只有输入密码才能阅读。
```

在项目根目录执行：

```sh
npm run encrypt -- _private/2026-09-24-私密笔记.md
```

终端会要求输入两次密码，输入过程不显示。密码至少 12 个字符，推荐密码管理器生成的随机长密码。密码不通过参数传递，不写入文件，也不会打印。

生成 `_posts/2026-09-24-私密笔记.md`，其中仅包含公开元数据、密文和固定提示文字。检查后提交生成文件与本功能相关代码，按现有流程推送到 GitHub 即可；不要提交 `_private/`。

访问文章页面，输入密码阅读。刷新页面或点击“重新上锁”后需要重新输入。浏览器需支持 Web Crypto，使用 HTTPS（本地预览可用 localhost）。解密不向服务器发送密码，也不使用 localStorage/sessionStorage 保存密码或正文。

## 修改文章或更换密码

修改 `_private/` 中的原文，再运行同一条命令。生成的同名密文文章会被覆盖；可以输入原密码，也可以设置新密码。提交更新后的 `_posts/` 文件即可。

忘记密码时，可使用保留的本地原文重新生成。已获得旧密文和旧密码的人仍能阅读旧版本，更换密码不能撤销旧版本访问。

## 将已有文章转为加密

先备份原文，再将文件从 `_posts/` 移到 `_private/`，保持文件名不变，然后执行加密命令。例如：

```sh
mv _posts/2026-09-24-私密笔记.md _private/
npm run encrypt -- _private/2026-09-24-私密笔记.md
```

脚本会拒绝覆盖同名普通文章，避免误操作。已有公开文章即使随后加密，原文仍可能存在于 Git 历史、搜索引擎缓存或他人副本中。此功能主要保护从未公开的新内容。

## 保护范围

- 加密的是正文。标题、文件名、日期、作者、标签、分类、链接仍公开；脚本只复制这些元数据，副标题和自定义字段不会自动复制。
- 首页和 RSS 使用固定加密提示，搜索索引仍只包含公开标题、日期和链接。
- Markdown 在本地转换为 HTML 后加密，支持常见标题、列表、表格、链接和代码块。原始 HTML 不执行，Liquid/Jekyll include 不解析；加密文章不生成侧边目录，代码块没有 Jekyll 服务端语法高亮。
- 图片和附件不会自动加密。正文中的图片 URL 虽被包在密文中，但图片或附件本身如位于公开仓库、图床或公开存储，依然能直接访问。敏感图片和附件不要按普通静态文件方式上传。
- 密文可被下载后离线猜密码，请使用强密码。此功能没有账户权限、密码找回或远程撤销功能。
- 解密后的正文存在当前浏览器内存中，访客仍可复制、截图。网站自身加载的其他脚本也属于信任范围。

## 验证

```sh
npm run test:encryption
```

覆盖中文正文往返、原文和私密字段不进入生成文件、错误密码、密文篡改、随机盐/IV、前端解锁及重新上锁。
